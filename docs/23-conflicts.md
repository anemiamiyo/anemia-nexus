# 23. 跨章节冲突与消解登记（v1.24 新增）

本章登记 v1.23 中"不同章节对同一件事给出两种口径"的问题，以及 v1.24 的消解结论。**评审时逐条核对；未登记者不代表不存在冲突，只代表尚未发现。**

| # | 冲突 | 涉及章节 | 消解结论 | 落地位置 |
|---|---|---|---|---|
| 23.1 | 内存预算只按单项目给，多根并行时可能叠加突破 | 16.2、5.7、19 | 引入全局预算 + 单 root 配额 + 准入控制 + 五级降级；多 root 并行不得突破全局预算 | 5.10、21.2 |
| 23.2 | 多处交互（根选择、写配置、repair 确认）在非 TTY 下会阻塞 | 5.7、5.8、11、22.2 | 逐场景定义 TTY / 非 TTY 行为；非 TTY 缺参数立即 64 退出并给完整命令 | 11.6 |
| 23.3 | "两分钟上手"与"30 万行全量 120s"被混为一谈 | 22.3、16.2 | 拆成 T1–T4 四个时间点，两分钟只覆盖"看到引导态到发出构建命令" | 22.3 |
| 23.4 | watch 模式声称"查询始终 fresh"，但 12.4 允许返回旧数据 | 14.1.2、12.4、15.2 | 统一五态状态机；`indexing` 期间不得标 fresh；只有显式 `acceptStale` 才返回旧数据且必须标注 | 12.4、14.1.2 |
| 23.5 | 符号 ID 含路径 vs 承诺重命名身份稳定 | 1.2、5.2、15.6 | 三元拆分（`symbolId` / `declarationLocator` / `identityConfidence`）；ID 不含路径；迁移靠证据 | 5.2、15.6、17.2-9 |
| 23.6 | 安全章节称"不执行项目代码"，配置章节允许加载 `.ts` | 18.1、5.8、22.2 | 六类操作分级；`.ts` 配置归 C6，需显式授权 + 子进程隔离 + 网络禁用 | 18.3 |
| 23.7 | CLI 参数示例与命令注册不一致（含拼接残留） | 11 | 重排为全局参数 / 专有参数两张表；删除拼接残留；补齐退出码与非 TTY 规则 | 11.2、11.3、11.5、11.6 |
| 23.8 | "零漏检"在 1.2 / 1.4 / 16.1 三处口径不同（一处无限定、一处为判据、一处为统计） | 1.2、1.4、16.1、8.1 | 统一为"确定性静态关系 + 覆盖完整 + 分析成功"；三分类 + `partial` 标记 | 1.2、1.4、8.1、16.1 |
| 23.9 | 退出码 2 既表示"仅告警"又可能承担"参数错误" | 11、16.3 | 0/1/2 语义不变；新增 64（用法）/ 70（内部）；分类由 `code` 承担 | 11.5 |
| 23.10 | `workspace.json` 被当作根集合的权威来源 | 5.7、5.8 | 定性为派生 + 缓存；权威为配置 + 各 root manifest；可重建 | 5.10.5 |
| 23.11 | 性能目标被当作已证明能力 | 16.2、21.2 | 明确为"待校准目标"；实测不达标按降级处理，不改口径 | 16.2.2、21.2.4 |
| 23.12 | 覆盖率无分子分母定义 | 5.12、14.1、19 | 统一五个指标的口径与排除规则；`semanticCoverage` 可为 null | 5.12 |

**维护规则**：新增或修改任何涉及"同一概念多章节出现"的内容时，必须在本章登记或更新对应行，否则视为文档缺陷。本章是评审的第一张检查表。
