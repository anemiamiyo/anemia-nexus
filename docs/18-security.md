# 18. 安全边界与降级

## 18.1 安全边界与操作分级（v1.24 重写，P0-03）

v1.23 的承诺是"不执行被分析项目的代码"。这句话在精确性上不够：加载 `.ts` 配置就是执行代码；跑 `verify` 就是执行命令；插件与分析器本身就是第三方代码。必须把"执行"拆成六类，逐类给出边界。

| 类别 | 具体行为 | 默认允许 | 边界与约束 |
|---|---|---|---|
| **C1 读取源码** | 读文件、算哈希、解析 AST | 是 | 不读项目根之外的路径；默认排除 `.env*`、密钥、证书、构建产物、依赖目录 |
| **C2 解析配置** | 读取并校验 `.nexus/nexus.config.json` | 是 | 只做数据解析，不执行；Zod `strict()` 拒绝未知字段 |
| **C3 执行 Nexus 自身代码** | CLI、索引器、查询层 | 是 | 自身代码可信；但不得借自身代码执行用户输入（禁止 `eval`、`new Function`、`require(用户字符串)`） |
| **C4 执行第三方分析工具** | scip-typescript、vue-tsc、postcss 等 | 是（白名单内） | 只允许 `package.json` 已声明的固定版本；禁止运行时下载；禁止自动安装 |
| **C5 执行用户自定义命令** | `verify` 的命令白名单、`vue.typeResolver` | **否**，需显式授权 | 见 18.4 |
| **C6 执行项目自身代码** | `.ts` 配置、`postinstall`、构建脚本、`node -e` | **否**，需显式授权 | `.ts` 配置见 18.3；项目脚本**永不自动执行** |

**核心不可协商项**：

1. **不得因打开项目、扫描目录、建立索引、响应查询或启动 MCP 而触发 C5 / C6。** 无一例外。
2. **不得隐式运行 `package.json` 的 scripts**（含 `prepare`、`postinstall`、`prebuild`），不得自动安装依赖，不得执行构建脚本或任意 shell 命令。
3. 不得默认允许网络访问；任何网络行为必须由用户显式开启，且在有网络的场景下也必须声明"将要访问哪些域"。
4. 自定义命令必须经 18.4 的授权流程；执行必须记录对象、参数、工作目录、退出码与输出摘要。
5. 执行必须有超时（默认 60s/条）、输出大小上限（默认 1 MB）、资源上限（继承 5.10 的预算）。
6. **一律不越界**：不读取项目根目录之外的路径；显式 `--include` 才放宽，且放宽记录写入 manifest。
7. **默认排除敏感文件**：`.env*`、密钥、证书、`node_modules`、构建产物、版本库与工具目录、缓存目录，与 12.5 的内置忽略基线同源。
8. **样式链额外约束**：不执行 Sass / Less 编译（不调用外部编译器、不加载插件），不解析 `url()` 指向的外部资源，不发起任何网络请求，不读取项目根之外的路径。
9. 索引目录写入权限最小化；`.nexus/` 默认不提交。

## 18.2 降级策略（必须显式声明，不得静默）

| 触发条件 | 降级行为 | 必须体现的字段 |
|---|---|---|
| tsconfig 无效或 typecheck 失败 | 进入 `syntax-only` 模式；禁用 references / impact 的确定性结论 | `mode: syntax-only`，`semanticCoverage: null` |
| SCIP 不可用或生成失败 | 退回语法索引；Surface 与引用结论降为 heuristic | 首行声明 + `relationClass` 全量降级 |
| Vue 语言核心不可用 | 组件降为语法级（Props 仅静态字面量可读） | `component: syntax-only`，`propsCoverage: 0/n` |
| 大文件 / 生成物 | 跳过并计入 `filesSkipped` | `filesSkippedBySize` + 原因 |
| 内存/并发不足 | 按 5.10.4 五级阶梯降级 | `degraded: [...]` + E20（若最终仍失败） |
| 映射失败（4.3） | 该符号标 `unmapped`，引用计数标 `partial` | `coverage.unmapped`，`counts.partial` |
| 身份无法确认（5.2） | 创建新 ID，旧 ID 标 `retired` / `unknown` | `identityConfidence: low` + E21（查询时） |

**降级的统一规则**：

1. 降级必须是**显式**的：写在 manifest、`status`、每次查询响应的首行或 `degraded` 字段里。
2. 降级不得改变对外承诺的措辞（例如 `syntax-only` 下不得说"已全部列出"）。
3. 降级不是错误：不阻断查询，但必须让调用方能判断结论强度。
4. 降级后若能力恢复，必须重新构建，不允许"混合档位"（同一索引内部分文件 normal、部分 syntax-only 时，必须在 coverage 中分别计数并标明）。

## 18.3 配置执行模型（v1.24 新增）

### 18.3.1 JSON 是默认，也是唯一被信任的数据格式

| 项 | 规定 |
|---|---|
| 默认文件 | `.nexus/nexus.config.json` |
| 校验 | Zod Schema + `strict()`；未知字段报 E17，不做"忽略并继续" |
| 字段白名单 | 所有可配置项必须在 Schema 中显式声明；Schema 之外无隐式行为 |
| 危险字段 | `commands.allow`、`vue.typeResolver`、`style.html` 三项必须在文档中单独标注风险 |
| 派生 | 由 Schema 派生 JSON Schema，供编辑器与文档共用（P2-03） |

### 18.3.2 TypeScript 配置 = 用户明确授权执行的可信代码

如果用户坚持使用 `.ts`（例如需要复用常量或做条件判断），必须满足全部七条：

1. 工具在首次加载前打印明确告知：**"该文件是可执行代码，加载即执行，可能读写文件或发起网络请求"**。
2. 未经授权不得加载。授权方式二选一：
   - 一次性：`nex <cmd> --trust-config`（仅本次进程有效）；
   - 持久：配置目录中写入 `.nexus/trust.json`（记录文件路径 + 内容哈希 + 授权时间），内容哈希变化即失效，需重新授权。
3. 未授权时：报 E18，并打印授权命令与风险说明；不得静默回落到 JSON（若存在 JSON 则用 JSON 并提示"已忽略未授权的 TS 配置"）。
4. 加载必须在**独立子进程**中完成（`node --experimental-strip-types` 或预编译），超时 5s，输出经 IPC 序列化后校验；禁止在主进程 `import()` 直接执行。
5. 加载期间禁用网络（`--no-network` 由子进程标志保证）并限制工作目录为项目根。
6. 加载结果必须经同一套 Zod Schema 校验；校验失败报 E17，不回落到默认值。
7. 每次加载记录：文件路径、内容哈希、授权来源（flag / trust.json）、耗时、结果摘要，写入 manifest 的 `configLoads[]`。

**禁止**：把 `.ts` 配置宣传为"更方便的配置方式"而不提可执行属性；在 `init` 时默认生成 `.ts`；在 CI 中默认信任 `.ts` 配置（CI 必须显式 `--trust-config`）。

### 18.3.3 双源与旧路径

- `.json` 与 `.ts` 并存 → E17，拒绝启动，列出两个路径，要求用户删除其一。
- 仓库根存在 `nexus.config.*` → E17，提示移动到 `.nexus/`；不做自动搬迁（会改动用户文件）。
- 配置中出现未识别的顶层键 → E17，列出键名与最近似合法键（编辑距离），便于修正。

## 18.4 自定义命令与第三方工具（v1.24 新增）

### 18.4.1 命令白名单与授权

```json
{
  "commands": {
    "allow": [
      { "id": "typecheck", "cmd": "npm", "args": ["run", "typecheck"], "cwd": ".", "timeoutMs": 120000 }
    ]
  }
}
```

规则：

1. 白名单只允许**完整命令 + 完整参数**，禁止通配符、禁止 shell 拼接、禁止管道与重定向。
2. 每条命令必须有 `id`、`cmd`、`args`、`cwd`（限于项目根内）、`timeoutMs`。
3. 首次执行前必须由用户确认（TTY 逐条确认；非 TTY 需 `--yes`），确认结果记录到 `.nexus/trust.json`，命令任一字段变化即失效。
4. 执行时逐条回显完整命令行、工作目录、超时；输出截断到 1 MB 并标注 `truncated`。
5. 未授权时：`postflight` / `verify` 跳过该命令并标 `skipped-unauthorized`，**不报 E12 阻断**；用户显式要求执行而未授权时，才报 E12。
6. 禁止：执行 `rm`、`git reset`、`git clean`、`git checkout --`、`sudo`、`curl | sh` 等破坏性或远程执行命令；白名单中出现此类命令直接拒绝并报 E17。

### 18.4.2 第三方工具与插件

1. 分析器与插件只允许来自 `package.json` 已声明的依赖，版本锁定。
2. 禁止运行时下载、动态安装、从 URL 加载插件。
3. 插件必须声明其能力（读文件 / 写文件 / 网络 / 子进程）；未声明能力的一律按"全禁"处理。
4. 插件在子进程中运行，崩溃不影响主进程；崩溃记为 `analyzer-failed` 并降级（18.2）。
5. **不可信插件**（未在官方清单内）默认禁用，启用需 `--allow-untrusted-plugin` 并在输出中持续标注。

### 18.4.3 安全测试项目（F17）

必须包含并全部通过：

| 用例 | 期望 |
|---|---|
| 恶意 `.ts` 配置：读 `~/.ssh/id_rsa` 并打印 | 未授权时不加载；授权后也因越界读取被拒（E09） |
| 恶意 `.ts` 配置：`fetch` 外网 | 未授权不加载；授权后网络被禁用，请求失败但主流程继续 |
| 恶意 `.ts` 配置：写 `/tmp/pwned` | 同上，写入被限制在项目根内（或直接拒绝） |
| `package.json` 带 `postinstall` / `prepare` | 全流程不执行，`node_modules` 无变化 |
| 恶意自定义命令（`rm -rf`） | 白名单校验拒绝，报 E17 |
| 未授权 `verify` 命令 | 跳过并标 `skipped-unauthorized`，退出码不受影响 |
| 不可信第三方插件 | 默认禁用；启用后持续标注 `untrustedPlugin: true` |

验收方式：`git status --porcelain` 为空、无新文件、无外网连接（CI 断网运行）、无子进程残留。
