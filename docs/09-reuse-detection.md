# 9. 复用性检测

v1.0 只有反向能力（Knip 报未使用），缺少防止"重复造轮子"的正向能力。本能力直接服务于"复用性"目标，列为 P0。

v1.24 修订（P1-06）：第一阶段**只用可解释的确定性规则**，向量相似度作为可选增强且不得成为正确性的唯一依据。原因是相似度分数天然连续，一旦作为主判据，AI 会把"0.87 相似"当成"语义等价"，进而误删或误用 API——这比不给结论更危险。

## 9.1 相似 API 检索

命令：`nex similar <symbol|自然语言描述> [--top 10] [--scope public|all] [--explain]`

### 9.1.1 第一阶段规则集（确定性、可解释）

| 规则 | 权重 | 判定方式 | 输出字段 |
|---|---|---|---|
| 名称词干相似 | 0.30 | 分词 + 词干化 + 同义词表，计算 Jaccard / 编辑距离 | `nameScore` + 命中词 |
| 参数个数一致 | 0.15 | 参数数量完全相同得满分，差 1 得半分 | `paramCountDelta` |
| 参数类型一致 | 0.20 | 逐位比较归一化类型文本；结构化类型比较到成员名集合 | `paramTypeMatches[]` |
| 返回类型一致 | 0.15 | 归一化类型文本比较 | `returnTypeMatch` |
| 模块位置 | 0.10 | 同一 architecture module 满分，同目录半分 | `sameModule` / `sameDir` |
| 导出范围 | 0.05 | 同属 Surface / 同属 internal | `surfaceScope` |
| 结构特征 | 0.05 | 是否为 hooks 命名（`useX`）、是否为组件、是否 async | `structuralTags[]` |

总分 = Σ(权重 × 分项得分)，但**排序必须同时输出每个分项**，不允许只给总分。规则版本号 `rulesVersion` 必须随输出返回，规则变化时旧结果不可与新结果直接比较。

### 9.1.2 可选增强：向量嵌入

- 默认关闭；开启需在配置中显式设置 `similar.embedding.enabled = true` 与本地模型路径。
- 必须离线可替换（本地模型或纯本地向量化），不得默认调用远程服务。
- 向量分数**只参与排序微调**，权重上限 0.15，且必须在输出中标 `usedEmbedding: true`。
- 禁止：用向量分数作为唯一依据；在报告里把向量分数表述为"语义等价"。

### 9.1.3 输出契约

每条候选必须包含：

| 字段 | 说明 |
|---|---|
| `candidate` | 符号名 + `symbolId` |
| `score` | 总分（0–1，两位小数） |
| `scoreBreakdown` | 各分项得分与命中证据 |
| `rulesVersion` | 规则版本 |
| `isHeuristic` | 恒为 true（相似度本身是启发式） |
| `matchBasis` | 命中的规则名列表 |
| `suggestion` | `reuse` / `extend` / `new` 三选一，并给一句理由 |
| `location` | `path:line:col` + 所属 root |

分档建议（用于 `suggestion`，阈值写在配置里，默认如下）：

| 分数 | 建议 | 含义 |
|---|---|---|
| ≥ 0.80 | `reuse` | 建议直接复用，先看现有实现是否满足 |
| 0.55 – 0.79 | `extend` | 建议扩展现有 API（加可选参数）而非新建 |
| < 0.55 | `new` | 建议新建，但需在 PR 中说明为何不复用 |

无候选时必须明确输出 `no-similar-found`，并附检索范围（scope、root、规则版本），不得只返回空数组。

**禁止**：把相似度结果表述为"等价""重复""可直接删除"；在无候选时返回"未找到"而不说明检索范围。

## 9.2 Preflight 中的已存在能力检测

Preflight 第 2 条（"检查是否已经有类似功能"）必须有可执行实现路径，而非口号：由任务描述与将要创建的目标符号，调用 9.1 得到候选集，按分档给出"建议复用 / 建议扩展 / 建议新建"三种结论，并把候选的 `path:line:col` 一并输出，供 Agent 直接阅读。

约束：当任务描述只有自然语言、没有目标符号名时，先用名称抽取得到候选符号名（可解释的关键词抽取，不使用模型），再做检索；抽取失败时明确输出"无法从任务描述中抽取符号名，请提供目标符号"，不得静默跳过该步骤。

## 9.3 重复实现巡检

命令：`nex audit-duplicates [--threshold 0.8] [--scope all]`

对全量符号做聚类，输出重复与近似重复分组，附文件位置与差异摘要。要求：

1. 聚类只使用 9.1.1 的确定性规则，不使用向量。
2. 每组必须给"差异点"（参数差异、返回类型差异、实现行数差异），不能只给相似度。
3. 该命令只报告，**不得自动合并或修改代码**。
4. 结果必须标注 `relationClass: heuristic`，并在报告首行声明"相似不等于等价，需人工确认"。
5. `--threshold` 低于 0.6 时给出警告（噪声过多），不阻止执行。
