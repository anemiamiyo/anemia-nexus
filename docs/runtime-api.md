# Node.js 内置 API 最低版本登记

> 本文件由 2.2「运行环境：五个概念必须分开」第 3 条与 3.1 选型结论要求建立。
> 职责仅限：登记项目使用的 Node 内置 API 及其最低版本。**不承载架构决策**。

## 1. 硬性口径

- 项目最低支持运行环境为 **Node.js 22.16.0**（`engines.node >= 22.16.0`，启动时校验，不满足即 E14 退出）。
- 构建产物 `target: node20` 只表示语法可被 Node 20 解析，**不是运行期 API 兼容性证明**。
- 新增任何 Node 内置 API，必须在本文件登记最低版本，并在同一次提交中确认与最低运行环境相容。
- CI 使用 `eslint-plugin-n` 的 `n/no-unsupported-features/node-builtins` 规则，以 `22.16.0` 为基准拦截越界 API（配置见根目录 `eslint.config.js`）。

## 2. 登记表

| API | 项目用途 | 最低版本 | 状态 | 依据 |
|---|---|---|---|---|
| `node:sqlite`（`DatabaseSync` / `StatementSync`） | 唯一权威存储驱动；禁止第三方 SQLite 驱动 | **22.16.0** | 设计已定，待 Phase 00 G6 探针确认 | 2.2、5.6；22.13 起免 `--experimental-sqlite`，22.16 起提供 `busy-timeout` |
| `util.styleText` | pretty 输出层的终端装饰，零依赖 | 22.16.0（由最低运行环境保证） | 设计已定，待 Phase 00 G6 确认具体 API 基线 | 3.1 第 8 条、15.7 |
| `fs.watch`（递归监听） | MCP watch 模式的文件变化信号 | 22.16.0（由最低运行环境保证） | 设计已定，待 Phase 00 G6 确认平台差异 | 14.1.2、12.4.3 |
| `AbortSignal.timeout` | 命令/任务超时与取消传播 | 22.16.0（由最低运行环境保证） | 设计已定，待 Phase 00 G6 确认 | 18.4、5.10.3 |
| `process.versions.node` | 启动时版本校验（E14）与构建指纹 | 随 Node 提供 | 设计已定 | 2.2 第 2 条、5.11 |

## 3. 维护规则

1. 表中「状态」为 **设计已定，待验证** 的条目，其版本结论必须在 Phase 00 G6 中用实际 API 探针复核后才能标记为「已验证」。
2. 未登记的内置 API 不得进入实现；确需使用时先补登记再提交。
3. 本文件不复制架构说明；涉及「为什么这样选」的内容引用 `02-technical-baseline.md` 与 `03-tech-stack-and-build.md`。
4. 当前仓库尚无运行时代码，本表为初始化阶段的**预登记**，不构成已验证结论。
