# 附录 A. Analyzer / Schema 兼容性矩阵

版本变化必须逐项回答三个问题：是否需要重新索引、是否需要迁移、是否允许直接启动。**不得合并成一个"是否兼容"的布尔值。**

| 变化类型 | 需要重新索引 | 需要迁移 | 允许直接启动 | 判定依据 |
|---|---|---|---|---|
| CLI 文案 / 帮助文本 | 否 | 否 | 是 | 不影响索引与数据 |
| 查询逻辑（不改变 Schema） | 否 | 否 | 是 | 结果可能不同，但数据有效；需在 CHANGELOG 说明 |
| 输出字段新增（向后兼容） | 否 | 否 | 是 | 15.2 字段只增不删 |
| 输出字段删除 / 语义变化 | 否（数据仍有效） | 否 | **否**（需升主版本） | 消费方契约破坏 |
| 查询逻辑改变确定性判定 | 视情况 | 否 | 是（但需重建以刷新 `relationClass`） | 建议 `--rebuild-affected` |
| 分析器版本变化（SCIP / TS / Vue Core） | **是**（全局） | 否 | 是（自动触发重建） | 12.1 |
| `symbolId` 算法变化 | **是**（全局） | **是**（历史表重算） | **否** | 不兼容，必须升 `schemaVersion` |
| 数据库 Schema 增列（可空） | 否 | 是（`ALTER TABLE`） | 是（自动迁移） | 迁移必须可回滚 |
| 数据库 Schema 改语义 / 删列 | **是** | **是** | **否**（需重建） | 5.5 不提供自动迁移 |
| Node 大版本变化（SQLite 内置版本随之变） | **是**（全局） | 否 | 是（自动触发重建） | 5.6 |
| 配置 Schema 不兼容变更 | 否 | 视情况（配置迁移提示） | 是（报 E17 并给修正建议） | 5.8 |

配套规则：

1. 每次发布必须在 CHANGELOG 标注上表所属行，不允许只写"小版本更新"。
2. "允许直接启动"为否时，CLI 必须拒绝启动并给出明确命令，不得"试着跑一下"。
3. 迁移必须可回滚：迁移前保留 `index.db.bak`，迁移失败即恢复并报 E06。

# 附录 B. 文档职责边界（P2-04）

| 文档 | 唯一职责 | 不该写什么 |
|---|---|---|
| 本任务书（技术设计） | 架构、数据模型、模块职责、接口与验收约束 | 逐步操作教程、具体安装命令的长篇解释 |
| `README.md` / `PROJECT.md` | 安装、运行、配置、上手顺序、能力边界 | 内部数据模型细节、实现取舍的历史争论 |
| `AGENTS.md`（宿主项目内） | 项目级 AI 协作规则、开发约束、关键入口 | 工具用法全集、错误码表 |
| Skill | 具体任务流程与专业操作步骤 | 架构说明、索引内容副本、错误码表 |
| 阶段报告 | 实施结果、测试证据、遗留问题 | 设计变更理由（应回写到本任务书） |
| `docs/runtime-api.md` | Node API 最低版本清单 | 架构决策 |

**冗余控制规则**：

1. 同一份规则只允许一个权威来源。需要重复表达时，其他位置必须写成引用（"见任务书 12.4"）而不是复制内容。
2. 错误码表、状态名、字段名三类内容**禁止**在多个文档中各存一份；一律引用本任务书。
3. 修改权威来源时，必须在同一次提交中检查所有引用点是否仍然成立。
4. 发现两处内容不一致时，以本任务书为准，并修正另一处；不得"两个都留着等以后统一"。
5. 文档版本与代码版本必须可对应：每个阶段报告注明所依据的任务书版本（如 v1.24）。
