# 19. 开发阶段与交付管理

采用阶段式开发，每个阶段必须单独验证、生成报告，并保留下一阶段交接文档。阶段通过条件（gate）不满足时不得进入下一阶段。

## 19.1 阶段总表

| 阶段 | 名称 | 输入 | 交付内容 | 通过条件 | 失败处理 |
|---|---|---|---|---|---|
| 00 | 可行性验证与定位校验 | v1.24 文档、候选项目样本 | 技术验证报告、最小原型、自动化验证用例、性能数据、风险与未解决清单、《项目描述文档》、MCP 协议探针记录 | 所有 P0 问题有**经过验证**的解决方案或已批准的架构调整；4.3.4 的 T01–T10 通过且 `falseMatchCount = 0`；三档 RSS 实测完成；MCP 探针通过并记录协商版本与拉起耗时 | 任一 P0 未通过 → 停止，提交架构调整申请（20.3），不得进入 01 |
| 01 | 骨架与 TS 索引 | Phase 00 结论 | CLI 骨架（17 命令 + 别名）、项目扫描、配置加载（JSON + 授权 TS）、TS/TSX 符号与引用索引、`status` / `doctor` 基础检查、退出码与错误码框架 | 单仓库可 build，引用结果与 tsserver 抽样一致；`--format pretty` 在 F01 可读且与 lines 条目数一致；非 TTY 默认 lines 断言通过；F17 的安全用例通过 | 修复后重跑；不得以"先跳过安全用例"推进 |
| 02 | Vue 语义与引用查询 | Phase 01 索引 | @vue/language-core 虚拟 TS、影子物化与坐标转译、`__VLS_` 过滤、Props/Emits/Slots、四类模板引用边、**4.3 的 Semantic Merger 与 symbol_map** | 4.1.7 的 V1–V4、V6 全部通过；`propsCoverage` 正常输出；映射未命中全部登记 | 修复；若映射率不达标，按 20.3 上报（不得降低门槛） |
| 03 | API Surface 与基线 | Phase 02 | Surface 判定（含 `evidenceSource` / `exportKind`）、api-snapshot、api-diff 分级、deprecated 链路 | Surface 判定无反向误报；每条记录都能回答"为什么是 public"；差分分级与人工判定一致 | 修复；`evidenceSource` 缺失即判不通过 |
| 04 | 关系图与架构分析 | Phase 03 | 依赖图、引用图、调用图（含三分类与四档置信）、架构规则、**S1 样式文件级依赖**、跨 root 边界规则 | 盲区清单 100% 标注；heuristic / unresolved 不进入确定性结论；S1 五类边全部可产出 | 修复；样式链不达标不阻断 05，但必须记为遗留项 |
| 05 | 影响分析与审计 | Phase 04 | impact、preflight、postflight、verify、CI 门禁与退出码、**5.9 查询期根路由** | 真实变更场景漏报率为 0（`certain` 口径）；报告含证据与盲区；E16 失败态正确 | 修复；不得以"人工确认"替代漏报率为 0 |
| 06 | 增量、性能与一致性 | Phase 05 | 失效传播、**12.3 提交协议**、锁、**12.4 状态机**、增量一致性门禁（12.2）、性能基准、内存预算、**5.10 全局调度器**、**5.11 构建指纹** | 增量与全量全字段等价；七注入点崩溃恢复通过；八类性能场景记录完整且达到 16.2 目标；内存落入 21.2 预算 | 若性能不达标 → 按 21.2 降级能力范围，不得调整口径；降级需负责人批准 |

## 19.2 贯穿性验收（不属于任何单一阶段，但每阶段末都要跑）

| 项 | 要求 |
|---|---|
| 构建可复现 | 同一 `buildFingerprint` 两次构建结果逐字节一致 |
| 输出可复现 | lines / json 在同指纹下逐字节一致 |
| 文档同步 | 本任务书、README、配置 Schema、AGENTS 模板四处口径一致（14.2、附录 B） |
| 无残留 | `git status --porcelain` 为空；`.nexus/tmp/` 为空 |
| 数据可解释 | 所有百分比指标都能给出分子分母（5.12） |

## 19.3 每个阶段交付物清单

- 阶段实施报告。
- 实际完成内容（按 implemented / partial / heuristic / unresolved / unsupported / failed 标注，20.2）。
- 测试与验证结果（含实际执行的命令与输出摘要）。
- 性能数据（适用时，按 16.2.3 字段）。
- 已知问题。
- 未完成事项。
- 依赖及架构变化。
- 对后续阶段的影响。
- 文档同步情况。
- 是否满足阶段验收条件的明确结论。

> 禁止为了赶进度将尚未实现的能力标记为已完成。禁止仅凭"编译通过"宣布阶段完成。
