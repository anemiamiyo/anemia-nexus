# 20. 禁止事项

这部分是专门针对 AI Coding Agent 的约束。分五组，共 48 条；编号为稳定引用使用，不得随意重排。

## 20.1 能力与承诺（01–10）

1. 禁止在没有技术调研的情况下自行开发已有成熟 npm 工具提供的能力。
2. 禁止为了追求功能数量引入不必要的依赖。
3. 禁止一次性实现全部模块而不进行阶段验证。
4. 禁止为了方便而将所有逻辑堆积在单个文件。
5. 禁止让不同分析器各自定义不兼容的数据格式。
6. 禁止将静态分析结果伪装成完整运行时事实。
7. 禁止未经授权修改被分析项目的业务代码。
8. 禁止忽略现有项目配置和锁文件。
9. 禁止无证据地宣称分析结果完整或 100% 准确；**"零漏报"只能限定为 `relationClass = certain` 且覆盖完整、分析成功**。
10. 禁止在没有回归测试的情况下宣称阶段完成。

## 20.2 关系与身份（11–16）

11. 禁止静默截断输出；任何裁剪必须可检测、可继续获取。
12. 禁止把 heuristic 或 dynamic-unresolved 关系作为确定性事实输出。
13. 禁止使用行号或内存引用作为符号身份；**也禁止把文件路径写进 `symbolId`**（5.2.2）。
14. 禁止在输出中包含时间戳、绝对路径、随机顺序等不稳定因素。
15. 禁止在降级状态下不声明降级即返回结论。
16. 禁止把 `low` 置信的身份迁移直接继承旧 `symbolId`，或在多候选时强行选一个（5.2.5）。

## 20.3 实现状态（17–22）

17. 禁止使用固定数据冒充真实索引。
18. 禁止使用模拟结果冒充真实语义分析。
19. 禁止使用硬编码关系冒充自动发现。
20. 禁止使用空实现冒充功能完成。
21. 禁止通过删除失败测试使测试套件变绿，或降低断言标准绕过问题。
22. 禁止在没有真实运行的情况下声称构建、测试或性能验证成功。

## 20.4 架构与数据（23–34）

23. 禁止把 Preflight / Postflight 等有副作用动作暴露为 MCP 工具（索引自维护的 refresh 不属于有副作用动作）。
24. 禁止把 Vue 影子文件或行号映射持久化到项目目录、`.nexus/` 或 SQLite；它们只允许作为构建期临时态存在。
25. 禁止引入第三方 SQLite 驱动（better-sqlite3、sqlite3 等），也禁止为其保留回退路径；Node 版本不足时应直接报 E14 并退出。
26. 禁止把样式类名或选择器做成 Symbol / Reference，禁止把样式边计入 TS references 计数或 API Surface。
27. 禁止宣称"样式消费方全集"；样式能力只能声明为文件级，动态路径与未解析别名必须计入 coverage。
28. 禁止把样式动态路径标为 direct，禁止为样式链执行 Sass / Less 编译或发起网络请求。
29. 禁止把多个 root 合并成单一索引；每个 root 必须独立 `.nexus/roots/<rootId>/`。
30. 禁止为未在 `package.json` 声明依赖的两个 package 造边，也禁止把 tsconfig paths、相对路径上跳或目录约定当作跨包依赖成立的依据。
31. 禁止把未声明依赖的跨包引用标为 direct 或计入 references 全集；只能记 unresolved(package-boundary) 并带原因。
32. 禁止在多根仓库的根选择上静默替用户决定；必须列出候选并显式选择，歧义时报 E15。
33. 禁止查询期用相对路径上跳、tsconfig paths 或"同仓库"假设去补另一个 root 的符号；禁止在 cwd 无归属时隐式扩成全包检索（必须报 E16）。
34. 禁止任一 root 构建失败后仍对外声称工作区索引完整；失败必须体现在 `failedRoots` 与 staleness 上。

## 20.5 输出与安全（35–48）

35. 禁止在 lines / json / markdown 输出 ANSI 转义序列（`/\x1b\[/` 必须为空）。
36. 禁止 pretty 为排版二次查询或二次排序；装饰层只能消费同一份查询结果。
37. 禁止 pretty 静默截断或省略完整性字段（`counts` / `coverage` / `truncated` / `nextCursor` / `staleness` 必须齐全）。
38. 禁止 MCP 通道暴露或回落至 pretty / markdown；非法 format 必须回落 lines 并令 `formatFallback=true` 可见。
39. 禁止对外宣称字号可调；终端没有字号 API，OSC 66 只能作为可失败的尝试。
40. 禁止在默认配置里索引构建产物与依赖目录（`dist`、`build`、`out`、`.next`、`node_modules`、`.git`、`.dsh`、`.agent` 等）；内置忽略基线只能追加，不能清空或静默删除。
41. 禁止配置文件双源（`.json` 与 `.ts` 并存，或仓库根存在配置文件）；发现即报 E17 并拒绝启动，不做静默合并。
42. 禁止 `init` 未经确认就落盘配置或索引目录；非 TTY 必须显式 `--write-config`。
43. 禁止在未授权的情况下加载 `.ts` 配置文件；禁止把 `.ts` 配置作为 `init` 的默认产物（18.3）。
44. 禁止隐式执行项目 `package.json` scripts、生命周期脚本、构建脚本或任意 shell 命令；禁止自动安装依赖。
45. 禁止把静态引用条数命名为调用频率、使用热度或真实调用次数（10.2）。
46. 禁止用未定义分子分母的百分比表示索引完整性（5.12）。
47. 禁止在增量与全量结果不等价时通过"取全量覆盖"掩盖缺陷，或调整比较口径放行（12.2）。
48. 禁止在 `doctor --repair` 中修改用户源代码、项目配置或自动安装依赖；修复范围仅限 Nexus 自身数据（P2-06）。

> 第一阶段尤其禁止直接跳到完整系统开发。必须先完成技术可行性验证，并确认选用的现有工具能够真实提供预期数据。

## 20.6 遇到架构级问题必须暂停并报告

Agent 发现以下任一情况时，**不得自行做出重大架构决定**：

- 现有技术路线无法满足核心需求。
- 现有数据模型无法保证一致性。
- 关键分析能力无法可靠实现。
- 安全承诺与实际技术机制冲突。
- 性能预算无法达到。
- 不同章节的约束无法同时满足。
- 需要改变公开接口或持久化数据结构。
- 需要删除或降级原设计中的核心能力。

必须提交一份《架构问题报告》，包含：问题描述、产生原因、影响范围、可选解决方案（≥2）、推荐方案、成本与风险、对既有阶段与文档的影响。等待项目负责人书面确认后再实施。**在等待期间不得继续推进相关实现。**---
