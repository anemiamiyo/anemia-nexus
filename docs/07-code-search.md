# 7. 代码检索能力

必须支持：

- 按名称查询符号。
- 按类型查询符号。
- 按文件查询。
- 按目录查询。
- 查询公共导出。
- 查询内部导出。
- 查询函数签名。
- 查询泛型和类型定义。
- 查询组件 Props、Emits、Slots。
- 查询函数和组件的引用。
- 查询 JSON 文件及其结构。
- 查询配置文件及其关键配置。
- 查询相关示例和测试。
- 查询废弃 API 及其替代方案。
- **查询符号的身份历史**（`--history`，读 5.2.6）。
- **查询某条关系的判定依据**（`--explain`，输出 `relationClass` + `confidence` + `evidence`）。

补充四条硬性要求：

1. 查询结果默认只返回摘要、精确位置和关联关系；只有明确要求时才展开完整源代码。
2. 任何列表型结果必须声明总数与是否完整（见第 15 章），不得只给前 N 条而无说明。
3. 无结果时必须区分以下五种情况，逐一给出不同文案与不同 `reason` 码：
   - `not-found`：确认不存在（覆盖完整且分析成功）
   - `not-covered`：索引未覆盖该区域（被 ignore / 未建索引 / 文件被跳过）
   - `ambiguous`：存在多个同名候选，已列出
   - `stale`：索引存在但已过期，结果可能不全
   - `analysis-failed`：该文件分析失败，结论不可用

   样式查询额外区分 `alias-unresolved` 与 `ignored`；多根仓库额外区分 `root-not-indexed`，并在结果中按 root 分组各自声明 coverage，不得跨根混排。
4. **禁止**把 `not-covered` 与 `analysis-failed` 合并成 `not-found`。三者在实现里对应不同代码路径，输出里必须是不同字段值。
